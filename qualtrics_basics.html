Question Block and Survey Flow

Qualtrics surveys are organized around question blocks. A default question block is added when you first create the survey:

Each question block can feature one or more questions within them. In this case, we have a single multiple choice question (Q1) albeit one without any content yet. In practice, you should include questions on the same topic within a question block. For instance, you might have a single question block for demographic questions (age, gender/sex, etc.), another for political ideology, another for a third topic, etc.

The top of the block provides the name of the question block which is “Default Question Block” in our current instance. We can rename this block by clicking on this text and giving the block a more informative name. You should do this in practice especially given that it will help you organize your survey later when working in the Survey Flow area of Qualtrics.

There are a couple of ways to add blocks to our survey. First, we can click “Add Block” to, well, add another block. Alternatively, we can click on the three dots in the block to get some block options, which includes “Add block below”. I believe this latter process is more useful when you already have many blocks already and do not want to scroll down to the end of the page to click the “Add Block” option.

Blocks are the basic building, uh, blocks of our survey. We can naturally move them around so that the survey progresses in the way we want. The block options menu shown in the image above has a “Move block” option that you can use to do so. However, this is a little awkward to use in practice and especially if you have a lot of blocks in your survey. A better option is to use the Survey Flow page. This area provides an overview of the basic flow of my survey. It indicates that respondent will first complete the question(s) in the “Default Question Block” block and then those in the “new block” area. Questions

Let’s turn to the process of creating/editing questions for our survey. We’ll begin with the default question to get a sense of how to edit questions and then move on to adding them and some of the options available to you.

Editing a question

Qualtrics has been nice to us and populated our Default Question Block with a multiple choice question:

At the top we can see “Q1”. This is the name of the question. When you add another question it will be “Q2” and so on. You can click on Q1 and edit it to what you want although I would likely do that at the very end, if at all. If you do rename questions, then do so in a way that will not create complications for you later on when analyzing the data. The name of the question will be the name of the variable in your eventual dataset after you download it from Qualtrics, so you would not want something that will create problems in R or SPSS. Personally, I use lower case whole words (e.g., “leftright” or “pid”) or snake case (e.g., “pid_lean”, “race_eth”) and keep them short but informative if/when renaming questions.

We then see “Click to write the question text” which is perhaps somewhat self-explanatory. We then see three multiple choice options; if we click on the text next to them we can write our answer options.

MC Question Options

If you click on a question, then you will see various options in the Edit Question column to the left of the question building area. Let’s talk about some of those:

Question Type: Here you can change the questions type. I’ll talk a little more about question types in the next section.

Answer Type: Can respondents choose multiple options or only one. The default is “allow on answer”. This is a sensible default for multiple choice questions. There can be situations where it makes sense to change this, but generally this can be left alone.

Choices: Here we can change the number of choice options. The default here was three but if we wanted to make this a 5-item or 7-item or whatever-item question, then we can increase/decrease the number accordingly.

Format: You get three options here: (1) list (what you see in the image), (2) dropdown (people pick from a dropdown box), and (3) select box (they’re giving a box with the different options and click on the one that they want). I would generally keep this as “list” for a multiple choice question.

Alignment: You can choose to show the response options in a vertical alignment (as above) or a horizontal one. I believe vertical alignment plays better with people taking surveys on mobile phones, so I might consider defaulting to that option.

There are some more options as well if we scroll down the page:

Add Requirements: (Note: this was off by default but I clicked it on so you could see the sub-options). The most relevant thing here is “Force response”. If you toggle Add Requirements and select this option, then respondents will need to answer the question to move on in the survey. Should you do this? There are pros and cons here. Selecting this option enables you to avoid having missing data on the question and thus maximize the number of survey responses that you can use in your analyses. In addition, it’s possible that you’ll need a response on an item for some other purpose (e.g., when you first ask them for informed consent to take the survey or because it will influence the nature of the questions people get later on in the survey). However, forcing people to respond might have negative implications for data quality as well insofar as it annoys respondents, and, moreover, respondents should have the right to not answer our questions. I would thus recommend using this option but including some type of explicit “Don’t Know” or “Prefer Not to Say” option as well.

Add Validation: You can ignore this.

Question Behavior: We now have a variety of options for question behavior.

  • Display and skip logic cover situations where you want respondents to be shown this question (or not shown this question) under certain circumstances. I’ll discuss this a little in a future section.
  • Carry forward choices enables you to “copy specific answer choices from a question and bring them into a future question in your survey”.
  • Choice randomization enables you to randomize the order of response options; I’ll discuss this a little more in the next section.
  • Recode values enables you to change the numeric values associated with each response. The default options in my question, for instance, are 1 = too little, 2 = too much, and 3 = about right. If I wanted to change that behavior (e.g., make too little = 1, about right = 2, and too much = 3), then I could use this option to do that. The potential advantage is that this may pre-empt having to do this type of recoding later on in R/SPSS. However, I generally leave this alone.
  • Default choices is an option area which I do not think I’ve ever actually used. It’s probably not relevant for your survey.
  • JavaScript: this would givey you the ability to add Javascript code to do some advanced things…but again, this is almost certainly not required for your survey.

Choice Randomization

One of the options noted above is Choice Randomization. Let’s take a look at what we can do here:

The default is “No Randomization” - the responses that you created will be shown in the order that you created them. For some questions this might not be problematic. The other options, meanwhile, enable you to randomize your responses in some manner.

Why (and when) might you want to randomize response options? Consider what it takes to answer survey question: we need to read and interpret this question, recall information from memory, and then try to map this information to the response options before us. Answering a survey question, in other words, requires some degree of mental effort. Ideally, respondents are willing and able to give this effort and thus answer our questions as well as possible. However, respondents may not always be so willing and able - perhaps they’re not so interested in the topic or the survey is dragging on a bit or the question simply requires a lot of effort to answer. In such cases respondents might engage in “satisficing” behavior - they might take some type of shortcut to come up with a good enough answer for themselves. This could involve simply relying on the most immediate considerations that come to mind rather than canvassing their memory for additional relevant information. Or, it could mean simply choosing the first option offered since that is a very simple way to get through a survey.1 This latter behavior would then induce a potential bias in our data with responses skeweed to the first response option given to respondents. Randomizing choice options does not really help with the former sources of satisficing behavior, but it can help reduce the negative impacts of the latter type of behavior. I thus recommend some randomization in your response options.

1 I recall being in college and receiving a telephone (!) survey from some university service. The interviewer would start reading out the response options, one after the other, and the survey starting to drag on and on…and my desire to satisfice in just this way growing and growing.

Let’s take a look at our options for choice randomization:

Display answers in a random order

This will completely randomize the order of the response options. If I were to select this option for my ‘are we spending too much’ question, then some respondents might get ‘Too Little | Too Much | About Right’ as the response order and others ‘Too Much | About Right | Too Little’ and others ‘About Right | Too Little | Too Much’ and so on. This option is thus not particularly useful for items where the responses have some type of ordinal scale to them (e.g., not at all to extremely; strongly agree to strongly disagree). Instead, this option is more useful for questions with unordered categorical responses (e.g., what is your nationality; which candidate/party did you vote for).

Present only _ of total choices

This enables you to select some random number of options to show. I cannot think of a particularly good use case for this.

Randomly flip the order of choices

Suppose that you have a question where there are five response options: strongly agree, agree, neither, disagree, strongly disagree. This randomization option will show some respondents the scale starting from strongly agree and going to strongly disagree but other respondents the flipped order, strongly disagree to strongly agree. I would recommend using this for your questions that involve an ordinal scale.

When you click on this option, you will then see a sub-option with a ticked box: “Consistently reverse the choice order for all questions with this randomization option selected.” The Qualtrics help page says the following about this sub-option: “This option only appears after enabling “randomly flip the order of choices.” When enabled, this option will consistently randomize answer choice order for all affected questions in your survey.” Suppose I set up my response options to range from strongly agree to strongly disagree - if Qualtrics randomly shows the respondent the question in the strongly disagree to strongly agree format (i.e., randomly flips the direction of the option) then it will also randomly flip the order for all subsequent questions where you ask it to randomly reverse the scale direction. Otherwise, Qualtrics will randomize the direction anew for each question. This is generally reasonable - having things flip around randomly from question to question can induce confusion among respondents and increase their cognitive load…which might lead them to satisfice!

Advanced Randomization

This enables some additional customization to the randomization process. Let’s take a peek at the options you get if you click on this and then “Set up Advanced Randomization”

We see the response options for my question in the left box, under “Fixed display order”. In essence, this shows us the current display order for the options. If we click on one of these options (or select them all), we can then add them to one (or more) of the boxes to the right. The most useful box here is “Randomize Choices”. This option is useful if we want to randomize the order of only some of the responses. For instance, suppose that my question asked respondents who they voted for in the 2024 US President election with the following options: Donald Trump, Kamala Harris, Jill Stein, Some Other Candidate, Did Not Vote. I might want to randomize the order of Trump, Harris, and Stein while leaving the other top options for the bottom of the list. I could do that by selecting the Trump, Harris, and Stein options and adding them to the “Randomize Choices” box at the top.

Adding New Questions

Thus far we’ve seen how to edit a question using the default question that Qualtrics populated our survey with as a base. Let’s talk, then, about adding new questions to our survey.

Adding new questions is pretty straight forward. Just hit “Add New Question” within a block and a menu will pop up showing different types of questions that you might add. Let’s talk about some of the possibilities.

Multiple Choice: This will likely be your bread and butter question type. We’ve seen it already so I won’t so more here.

Text Entry: This is for situations where you want to ask an open ended question.

Text / Graphic: This type of ‘question’ doesn’t actually ask respondent a question per se since respondents are not provided with any response options. Instead, respondents just see some text. This type of question is particularly useful for creating segues between areas of your survey. For instance, suppose you begin with questions about people’s political values and then segue into questions about their attitudes toward globalization (or whatever). You might start the first block with a Text question that says something like “We’ll begin by asking you some questions about your political attitudes” or something like that.2 You might then include another Text ‘question’ as a segue to the following section as well, “We’ll now ask you questions about your beliefs regarding globalization”. Another use case for this type of question are experiments, e.g., providing the stimulus or the treatment that people are responding to.

2 Alternatively, you might have segue Blocks that only feature this single question instead of incorporating it into the same block as the resulting questions. That can be useful if, for instance, you want to randomize the order of questions in the ensuing block. See the CHAPTER XX for more on randomization.

Matrix Table: You can think of this as a way of asking several multiple choice questions on the same topic in a slightly more efficient manner. For instance:

Here, respondents are asked to indicate whether they want more or less spent in four different areas. We can add/reduce the number of statements or the number of scale points for the question via the options to the left. While not shown here, one can also randomize the order of the different statements within the grid, which is generally a good idea.

This type of grid or matrix question can be useful when you have several items that share a common prompt/intro and have the same scale, i.e., the questions all deal with the same basic concept. The main trade off here is complexity. The table above only had four statements from which to choose. This type of set up would not work very well if there were many different rows/statements (although it might be reasonable to have two or three such tables rather than one giant one). This type of set up can also be awkward to answer on a mobile phone. Page breaks

Qualtrics surveys are organized around question blocks (see Section 1.3). Each block can feature one or more questions. I would recommend including multiple blocks within your survey with each organized around a common theme or common concept.

You should include page breaks within blocks that feature multiple questions. You can add a page break by moving your mouse cursor to the area between questions at which point an “+ Add page break option will come up”:

This is how things will look after clicking on the option:

In general, I would recommend limiting the number of questions on a single page to keep the survey manageable for your respondents. I typically default to a single question per page although there are some areas where I might have two or three (e.g., basic demographics).

There are some places where I might deviate from this suggestion. For instance, suppose I am interested in measuring some latent psychological concept that is typically measured via a somewhat long multi-item battery (e.g., need for cognition or the Big Five personality traits). I would not have twenty different pages for each question in the (short) Big Five inventory, but likely four or five pages each with multiple questions. This might be a place where a grid question would be useful.

Timing questions

One question type not discussed above but which may be useful to you are timingquestions. A timing question does what it says - it records how long respondents take on the survey page. We can add it via the Add a new question as seen below. Q4 is what the timing question looks like within the question block.

The Timing question will record four things for you:

  • How many seconds before the first click on the page (First Click)
  • How many seconds before the final click on the page (Last Click)
  • How many seconds before the respondent clicked to the next page, i.e., submitted their response (Page Submit)
  • How many times they clicked on the page (Click count)

The most useful thing here is the Page Submit entry. This can be particularly useful for thinking about (or even analyzing) how long people thought about the question you are asking.

One thing to note here: be mindful of the page breaks here. The Timing question focuses on how long people take on the page as a whole. If you want to measure how long they take on a specific question, then that question should be provided on its own separate page by inserting page breaks before and after the question (and making sure the Timing question is also placed within those page break boundaries).

The Timing question is mainly used to track how long people take. However, we can also use it in an additional aspect: you can also use this option to make sure that respondents sit on the page for a give amount of time before being allowed to progress to the next page. This is sometimes used to prevent respondents from simply speeding through the survey and for increasing the chances that they engage with the material on the page. I would use that option sparingly if at all. See the Qualtrics page for this question (linked above) for more.

Piping, Skipping, and more

Most of the time we ask a respondent a question and their answer does not matter for the rest of the survey. However, there can be scenarios where we might want to have a person’s answer to a question influence the nature of future questions. This section discusses some possibilities.

Display Logic

One way we can use people’s responses to influence the rest of the survey is via Display and Skip logic. In essence, these cover situations where we want to display a subsequent question to respondents based on their response to an initial one or, alternatively, to skip questions based on prior responses. I’ll give an example of the former in this sub-section.

A classic example here involves the measurement of partisan identification in the United States. The most common method is to first ask respondents a question such as: “Generally speaking, do you think of yourself as a Democrat, a Republican, an Independent, or what?”. Respondents who select Democrat or Republican are then asked for the strength of this identification (is it strong or not very strong). Respondents who indicate Independent, or Other Party, or No Preference are instead given a follow up question where they are asked “Do you think of yourself as closer to the Republican Party or to the Democratic Party” with three response options: Closer to Republican, Closer to Democratic, or Nether. In this set up we need to ask respondents an initial question and then have our survey show them a specific follow up question based on their initial response. We can do this via Display Logic.

Skip Logic and Consent Pages

Earlier we saw how to selectively display questions based on responses to an initial question. We can use Skip Logic to similar ends: use the response to one question to inform whether Qualtrics skips a subsequent question (or questions).

Perhaps the most relevant place to use Skip Logic is in combination with your very first question on the survey: the informed consent question. Every survey should begin with a question informing respondents about the basics of the survey and asking them for their informed consent. Respondents who answer affirmatively here can take the survey while those that do not give consent do not - they should, in essence, skip the entire survey.
